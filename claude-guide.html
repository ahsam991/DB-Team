১

Setup ঠিক করুন

ভিত্তি মজবুত হলে বাকি সব সহজ

01

Local file নিয়ে কাজ করতে হলে Claude Desktop ব্যবহার করুন

আপনার কম্পিউটারের local files নিয়ে সরাসরি কাজ করতে Claude Desktop গুরুত্বপূর্ণ। এতে Claude অনুমোদিত local folders ও files অ্যাক্সেস করতে পারে। Cowork এখন web ও mobile-এও পাওয়া যায়; তবে local file access-এর ক্ষেত্রে Desktop app-এর প্রয়োজন হতে পারে।

02

ছোট প্রশ্নে Chat, বড় কাজে Cowork

সাধারণ প্রশ্নের জন্য Chat যথেষ্ট। কিন্তু research, data analysis, document creation, file organization বা অন্য কোনো multi-step কাজ হলে Cowork ব্যবহার করুন। Message box-এর নিচে Cowork নির্বাচন করে কাজের desired outcome বলুন।

Multi-step কাজের জন্য
03

কাজ দিয়ে চলে যেতে পারেন

Cowork-এর remote sessions আপনার কম্পিউটার বন্ধ থাকলেও চলতে পারে। তবে কাজটি যদি local files বা local computer access-এর ওপর নির্ভর করে, Desktop app-এর connection প্রয়োজন হতে পারে।

04

বারবার ব্যবহার করা files Project-এ রাখুন

একই documentation, dataset, research papers বা reference files বারবার upload করার দরকার নেই। যে কাজগুলো একই context-এর মধ্যে করেন, সেগুলো একটি Project-এ রাখুন। Project-এর knowledge সেই Project-এর chats-এ context হিসেবে ব্যবহৃত হয়।

05

Project Instructions একবার ঠিকভাবে লিখুন

আপনার কাজের context, preferred tone, output format, terminology, formatting rules, কী করতে হবে আর কী করা যাবে না — সব Project Instructions-এ লিখে রাখুন। তাহলে প্রতিটি নতুন chat-এ একই নির্দেশনা বারবার দিতে হবে না।

Rule of thumb“কী করবে” শুধু নয়, “কী করবে না”ও লিখুন।
06

একই কাজ বারবার করলে Skill বানান

একই workflow বা instruction বারবার দিতে হলে সেটাকে Skill বানান। Skills specialized, repeatable workflow-এর জন্য তৈরি। Free, Pro, Max, Team ও Enterprise — সব plan-ই এতে আছে; শুধু Code execution enabled থাকতে হয়।

Repeatable workflow → Skill
07

প্রয়োজনীয় Apps ও Connectors-ই connect করুন

যে external app বা service সত্যিই দরকার, শুধু সেটাই connect করুন। অপ্রয়োজনীয় access দিলে complexity বাড়ে—agentic কাজের ক্ষেত্রে ভুল action-এর impact-ও বাড়তে পারে। তাই permission দেওয়ার আগে Claude কী access পাবে তা বুঝে নিন।

২

কাজের গতি বাড়ান

দ্রুত ও দক্ষ হতে ৯টি অভ্যাস

08

Work, Client ও Personal কাজ আলাদা Project-এ রাখুন

একটি Project-এ সবকিছু রাখবেন না। Research এক জায়গায়, client work অন্য জায়গায়, personal work আলাদা জায়গায়। Project-এর context ও memory আলাদা থাকায় relevant information বেশি focused থাকে।

09

Chat এলোমেলো হলে নতুন chat শুরু করুন

একটি conversation-এ অনেক ভুল direction, correction ও unrelated discussion জমে গেলে নতুন chat শুরু করা বেশি কার্যকর। প্রয়োজনে আগের chat-এর final context বা গুরুত্বপূর্ণ সিদ্ধান্ত নতুন chat-এ দিন।

10

উত্তর পছন্দ না হলে message edit করুন

একই prompt আবার নতুন করে লিখে শুরু করার বদলে আগের message edit করে নতুন direction দিন। এতে conversation-এর অপ্রয়োজনীয় অংশ না টেনে desired direction-এ যাওয়া সহজ হয়।

11

Model selector ব্যবহার করুন

Message box-এর আশেপাশে থাকা model selector থেকে available model পরিবর্তন করা যায়। বর্তমান interface-এ model-এর পাশাপাশি effort ও extended thinking-এর মতো reasoning options-ও পাওয়া যেতে পারে।

12

কঠিন কাজে effort বাড়ান

Routine task হলে কম effort যথেষ্ট। কিন্তু complex reasoning, debugging, planning বা difficult analysis-এর ক্ষেত্রে higher effort ব্যবহার করুন। মনে রাখবেন—higher effort সাধারণত বেশি compute/token ব্যবহার করে।

Complex কাজে high effort
13

Complex reasoning-এ Extended Thinking

Math, logic, debugging, optimization বা complex planning-এর মতো কাজে Extended Thinking কাজে লাগতে পারে। তবে প্রতিটি ছোট প্রশ্নে চালু রাখার প্রয়োজন নেই।

14

শুধু Steps নয়, Outcome বলুন

প্রতিটি ছোট step আলাদা করে বলে দেওয়ার দরকার নেই। বরং বলুন—আমি এই result চাই, context এটা, এবং এই constraints মেনে কাজ করো। তারপর Claude-কে approach তৈরি করতে দিন।

Prompt pattern“আমি এই result চাই, context এটা, এবং এই constraints মেনে কাজ করো।”
15

কথা বলে Brief দিন

দীর্ঘ explanation টাইপ করার চেয়ে voice-এ পুরো context বলা অনেক সময় সহজ। বিশেষ করে research idea, project requirements বা brainstorming-এর ক্ষেত্রে বিস্তারিত brief দিলে Claude-এর কাজের context ভালো হয়।

16

Usage ও Context দুটোই manage করুন

লম্বা conversation, বড় attachment ও একসঙ্গে অনেক tools/connectors ব্যবহার করলে usage ও context দ্রুত বাড়ে। Routine কাজে Chat, complex multi-step কাজে Cowork ব্যবহার করুন; অপ্রয়োজনীয় tools ও extended thinking বন্ধ রাখুন।

৩

Security ও Privacy

ডেটা সুরক্ষায় ৪টি নিয়ম

17

Password, API Key, NID বা Bank Details paste করবেন না

প্রয়োজন হলে YOUR_API_KEY, YOUR_NID, ACCOUNT_NUMBER-এর মতো placeholder ব্যবহার করুন। তারপর final জায়গায় নিজে sensitive information বসান।

Security firstPlaceholder ব্যবহার করুন, পরে নিজে বসান।
18

Sensitive conversation-এর জন্য Incognito Chat

Incognito Chat temporary conversation হিসেবে কাজ করে। এগুলো regular chat history-তে save হয় না এবং future memory-তেও যোগ হয় না। তবে সম্পূর্ণ সংরক্ষিত হয় না—Anthropic-এর policy অনুযায়ী default retention 30 দিন হতে পারে, এবং organization-এর retention policy প্রযোজ্য হতে পারে।

19

Memory-তে কী জমা আছে দেখে নিন

Settings → Memory-তে গিয়ে Claude আপনার সম্পর্কে কী মনে রেখেছে তা review করুন। ভুল বা outdated information থাকলে edit বা delete করুন। চাইলে memory pause বা reset-ও করতে পারেন।

20

বেশি তথ্য মানেই ভালো উত্তর নয়

১০টি file upload করার আগে নিজেকে জিজ্ঞেস করুন—“এই কাজের জন্য আসলে কোন files দরকার?” অপ্রয়োজনীয় information বাদ দিলে Claude-এর জন্য relevant context খুঁজে পাওয়া সহজ হয়।

Ask yourself“এই কাজের জন্য আসলে কোন files দরকার?”
৪

নিজের বিচারবুদ্ধি ব্যবহার করুন

AI-কে blind trust নয়

21

Confident answer মানেই correct answer নয়

বিশেষ করে সংখ্যা, তারিখ, statistics, citations, URLs, legal বা financial information নিজে cross-check করুন।

22

Claude-কে আপনার ধারণার বিপক্ষে argument দিতে বলুন

শুধু “আমি ঠিক কি না?” জিজ্ঞেস করবেন না। বরং বলুন—“আমার এই ধারণার বিরুদ্ধে সবচেয়ে শক্তিশালী যুক্তিগুলো দাও।” এতে confirmation bias কমাতে সাহায্য করে।

Anti-bias prompt“আমার এই ধারণার বিরুদ্ধে সবচেয়ে শক্তিশালী যুক্তিগুলো দাও।”
23

নিজের কাজ নিজেকেই audit করতে দিন

লেখা বা analysis শেষ হওয়ার পর বলুন—“এই লেখায় factual error, contradiction, weak assumption এবং unsupported claim আলাদা করে বের করো।” একই output-এর second-pass review অনেক ভুল ধরতে পারে।

24

AI output-কে Draft হিসেবে দেখুন

Claude-এর output সরাসরি final ধরে নেবেন না। বিশেষ করে যে বিষয় আপনি নিজে পুরোপুরি বোঝেন না, publish বা submit করার আগে verify করুন।

৫

যেগুলো অনেকেই ব্যবহার করেন না

Advanced capability + ৩টি prompt

25

Research + Critical Thinking ব্যবহার করুন

গভীর research-এর জন্য Claude-এর Research feature ব্যবহার করতে পারেন। এটি একাধিক search চালিয়ে বিভিন্ন source ও angle থেকে তথ্য সংগ্রহ করে citations-সহ report তৈরি করে। বর্তমানে Research paid Claude plans—Pro, Max, Team ও Enterprise-এর জন্য available এবং Web Search enabled থাকতে হয়।

বড় কাজ শুরুর আগে এই ৩টি prompt ব্যবহার করুন

প্রশ্ন করুন

“শুরু করার আগে এমন ৩টি প্রশ্ন করো, যেগুলোর উত্তর না জানলে কাজটি ভুল হতে পারে।”

Approach চান

“৩টি সত্যিকারের আলাদা approach দাও এবং প্রত্যেকটির trade-off ব্যাখ্যা করো।”

নির্বাচন করান

“এখন সবচেয়ে শক্তিশালী approach নির্বাচন করে কেন সেটি বেছে নিলে তা ব্যাখ্যা করো।”

★

কয়েকটি Pro Tip

পেশাদারদের কাছে এগুলো common sense

Project Instructions-এ শুধু “কী করবে” নয়, “কী করবে না”ও লিখুন।

একই prompt বা workflow বারবার ব্যবহার করলে সেটাকে Skill বানান।

Output format পছন্দ হলে সেই preference স্থায়ীভাবে relevant instructions বা style-এ রাখুন।

বাংলায় লিখতে চাইলে বলুন: “Technical terms English-এ রাখবে, explanation Bangla-তে দেবে।”

Client বা confidential document নিয়ে কাজ করলে Incognito ব্যবহার করুন এবং data retention policy বুঝে নিন।

AI-কে শুধু প্রশ্ন করার বদলে workflow হিসেবে ব্যবহার করুন—এটাই সবচেয়ে বড় পার্থক্য।

৫ মিনিটের Quick Start

প্রথম মিনিট

Settings → Capabilities দেখে Code execution ও file creation enabled আছে কি না নিশ্চিত করুন।

দ্বিতীয় মিনিট

সবচেয়ে বেশি করা কাজের জন্য একটি Project তৈরি করুন।

তৃতীয় মিনিট

Project Instructions-এ role, context, tone, formatting, workflow ও do/don’t নিয়ম লিখুন।

চতুর্থ মিনিট

Settings → Memory গিয়ে Claude কী মনে রেখেছে তা review করুন।

পঞ্চম মিনিট

একটি কঠিন প্রশ্নে higher effort / Extended Thinking ব্যবহার করে normal setting-এর সাথে পার্থক্য দেখুন।

শেষ কথা

এই তালিকার সবচেয়ে গুরুত্বপূর্ণ বিষয়গুলো আসলে কোনো “secret trick” নয়। AI-কে শুধু প্রশ্ন করার বদলে workflow হিসেবে ব্যবহার করুন—তাহলেই Claude শুধু “উত্তর দেওয়ার tool” না হয়ে আপনার কাজের একটি structured collaborator হয়ে উঠতে পারে।
